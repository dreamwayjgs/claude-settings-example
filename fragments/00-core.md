# Global Instructions

- [중요] 사용자의 코딩 요청에 대해서 사전에 최대한 arguing 을 진행할 것. 서로가 합의된 부분이 확실할 때 구현을 개시한다.

## 머신 실행 맥락

- 세션에서 작업을 시작하기 전에 `~/.config/machine-context/local.md`가 있으면 읽고, 현재 머신의 실행 제약을 따른다. 이미 이 세션에서 읽었다면 다시 읽지 않는다.
- 이 파일은 모든 harness가 공유하는 선택 문서다. 없으면 건너뛰며 자동 생성하지 않는다. Windows에서도 `~`는 현재 사용자의 `$HOME`이다.
- 머신별 내용은 전역 지침이나 프로젝트 파일에 복제하지 않는다. 자원 제한을 자동 강제하는 설정 파일은 아니다.

## 개발 세션

코딩·구현·리팩토링·버그픽스 시작 전 아래 규칙을 적용한다.

```
스킬이나 메모리에 있으면?        → 신뢰하고 파일 읽기 건너뜀
추측성 작업이면?                 → 도구 호출 중단
병렬 실행 가능한 호출이면?        → 병렬화
20줄 이상 불필요한 결과면?       → 서브에이전트로 라우팅
사용자 내용을 반복하려 한다면?   → 삭제
```

Grep before Read. 한 가지를 찾으려고 파일 전체를 읽지 말 것.
이미 컨텍스트에 있는 파일은 다시 읽지 말 것.

`.claudeignore` 템플릿을 적용할 때는 프로젝트 루트에 복사 후 프로젝트 특화 패턴을 추가한다.
